# 文件迭代、暂存与恢复

## 修改前

读正在使用的工作 HTML、规则来源和已有文字。备份该文件；保留 artifactId、snapshotId、页面／记录／说明 ID 和计数器。不要用重新初始化、批量升级或清缓存代替迭代。仅修改本次范围；页面归属来自文件配置。

浏览器暂存与磁盘文件可能不同。能在授权环境取得当前可编辑副本时，以实际副本核对；取得不到时，说明磁盘修改没有读取用户未保存的浏览器内容。不要因为文件旧就把它当成完整的用户当前状态。

## 新运行时的合并

暂存记录仍在原 `prototype-workbench:v3:<artifactId>:<snapshotId>` 键，内容为 `model`、`baseModel`、`cacheReview`。baseModel 是产生暂存时的文件模型。无须人为递增版本或轮换身份来触发检测。

打开同一文件时对比：当时文件、现在文件、浏览器编辑。

- 只有文件改了该项：使用新文件。
- 只有浏览器改了该项：保留浏览器内容，包括用户主动清空的正文。
- 双方独立修改不同字段：合并；带唯一稳定 id 的数组按记录合并，不按行号对齐。
- 双方改同一项：把两份内容记录在 cacheReview.pending；正文／说明先保留用户暂存，其他数据先使用文件，顶部明确显示核对入口。用户逐项选择后，两份及选择结果进入 resolved 归档。
- 新页面从文件加入，旧页面或业务结构已不兼容时不强行套用缓存；保留完整候选内容供核对，不能把它静默丢掉或宣称自动迁移成功。

旧缓存没有 baseModel 时无法推断编辑先后。独立的用户文字和有效视图进度保留；差异业务数据或同一段正文进入核对，不盲目覆盖。旧内容中的未知字段和原迁移归档继续保留。

冲突未处理时阻止只读／PRD 交付导出；可编辑副本始终可保存，包含冲突候选与归档，以便继续处理。只读文件启动以文件模型为准，不能由查看者旧缓存修改已交付正文和说明。

## 适用边界

这是新版文件运行时的能力，不是访问或迁移任意浏览器缓存的工具。不会自动修改其他工作 HTML。旧工作文件在用户要求升级时才接入；先在副本复现并检查其业务模型、缓存校验和导出入口。旧结构无法自动恢复时，保留候选文字、草稿及数据，按其原页面结构迁移后再验证。

正文迁移仍按 [PRD 约定](prd-template.md)；不得将旧章节再次自动塞进全局描述。升级旧文件时不删除用户已写文字、原始模型或附件。

## 验证

`node scripts/verify_revision.cjs` 覆盖同身份文件更新、独立用户正文、同字段冲突与处理、用户清空、稳定记录合并、新页面、无基线旧缓存和只读边界。临时 localStorage 只在隔离运行环境中使用。

真实浏览器再用隔离文件核对：先输入正文，修改该文件的另一字段后重开，确认两份修改都在；同一字段修改时能对照、选择并重开。不要用用户正在编辑的页面做破坏性验证。
