# 文件保存、迭代与恢复

## 默认：打开即编辑

每个编辑版 HTML 配套绑定该文件的本地入口。`init_prototype.py` 默认调用 `prepare_workbench.py` 生成；迭代或转换后，对实际文件调用 prepare，不能重新初始化已有内容。macOS 生成 `文件名-打开工作台.app`，程序及运行记录放在同目录 `.workbench/`。启动入口用相对路径寻找 HTML，只需 Python 3，不安装常驻系统服务。

`serve_workbench.py --launch 文件.html` 启动或复用仅监听 127.0.0.1 的保存程序，并打开浏览器。它只提供这个 HTML 和它的保存接口，不开放目录或任意文件写入。随机入口令牌、Host/Origin 校验及不开放 CORS 阻止其他页面直接写入。无页面心跳 30 分钟后停止；再次打开入口自动启动。

响应临时注入 `workbench-local-save`，携带文件名、保存接口及文件 SHA-256，不写进原文件。浏览器无需文件选择器：正文和草稿变化防抖 250ms 自动提交，收到文件读回确认才显示「已自动保存」。不同浏览器重新打开同一入口，都读取同一个磁盘文件。

保存请求只带模型、冲突候选、文件身份和预期 SHA-256。程序持有单文件锁，版本或身份改变则拒绝覆盖。仅替换 `prototype-data`，保留业务代码、文件与快照身份；写入临时文件、fsync、原子替换后读回。`.workbench` 保留一份写入前副本。服务失败、断开或冲突保留当前输入，不显示已保存；未落盘关闭时提醒。

可编辑副本及只读导出必须移除 `workbench-local-save`，不带保存接口连接或令牌。导出的只读 HTML 独立查看，业务交互保留，无正文或标注编辑入口。

## 编辑入口与离线兼容

初始化返回的 `editEntry` 是默认编辑入口，`file` 是其已绑定的存储目标。代理生成、迭代或转换时负责完成绑定，并把编辑入口作为日常使用的主链接；不要让用户寻找文件或再手动连接。`--html-only` 仅用于隔离验证。不要把 Skill 源模板、file:// 页面或离线副本作为已启用自动保存的交付结果。

不再使用 File System Access API、文件选择器或 IndexedDB 文件句柄。所有写入都走已绑定的本机保存接口；Ctrl/Cmd+S 只触发当前接口保存。说明提交立即写入；正文和未完成草稿输入后自动写入，失焦时立即尝试。顶部显示等待、正在保存、已自动保存或失败；仅收到文件读回确认后显示成功。

直接打开 HTML 的旧用法保留离线浏览和缓存恢复能力，但始终明确标注「离线暂存 · 未写入 HTML」。不弹选择器，不自动下载副本，不把缓存当成文件保存成功。已有用户浏览器缓存不删除；手动可编辑副本保留为数据恢复方式。只读文件没有写入、重试保存或编辑入口。

## 启动入口验收

macOS 的 `osacompile` 会在编译时签名。绑定的 `launch.command` 写入后，必须对最终应用重新签名并验证，不能继续使用资源变更前的签名。打包时仅清理自建应用中签名不允许的 FinderInfo 和 ResourceFork，保留隔离、来源及其他属性，不关闭系统安全检查。

交付前用系统原生入口实际启动目标应用（例如 `open "实际入口.app"`），读回对应 `.server.json`，核对文件与进程，再检查健康接口、实际页面和自动保存连接。只执行内置 shell、检查包存在、`open` 返回成功均不证明应用已经可用。Finder 后续可能补充目录元数据，因此打包时严格验证签名，交付时还要验证资源完整性及原生启动。

首次打开位于桌面等受保护目录的工作文件，macOS 可能请求访问该目录。此时由用户在系统提示中确认；未确认前报告“等待系统授权”，不能替用户操作授权，也不能冒称打开或保存成功。这与网页选择工作文件无关，仍由入口绑定同一 HTML。

服务启动成功后，可直接在当前对话打开已核验的本机网页，并保留应用入口供下次重新启动。网页地址只在该服务存活期间有效；不要将闲置退出后的旧地址作为永久入口。用于验收的临时服务结束后清理，明确区分用户正在使用的工作台服务。

## 多窗口备份

浏览器缓存只作恢复备份。写共享缓存前，按上一次观察到的正文基线合并其他窗口的独立修改；同一字段冲突保留双方，独立新增说明的编号碰撞需保留两条记录。每个窗口另外保留独立的最近文字备份，防止旧版窗口覆盖共享缓存。旧缓存没有基线时，缺失记录不是删除证据；不能用当前文件冒充旧基线，吞掉已经恢复的说明。

## 修改前

读正在使用的工作 HTML、规则来源和已有文字。备份该文件；保留 artifactId、snapshotId、页面／记录／说明 ID 和计数器。不要用重新初始化、批量升级或清缓存代替迭代。仅修改本次范围；页面归属来自文件配置。

浏览器暂存与磁盘文件可能不同。能在授权环境取得当前可编辑副本时，以实际副本核对；取得不到时，说明磁盘修改没有读取用户未保存的浏览器内容。不要因为文件旧就把它当成完整的用户当前状态。

## 新运行时的合并

暂存记录仍在原 `prototype-workbench:v3:<artifactId>:<snapshotId>` 键，内容为 `model`、`baseModel`、`cacheReview`。baseModel 是产生暂存时的文件模型。无须人为递增版本或轮换身份来触发检测。

打开同一文件时对比：当时文件、现在文件、浏览器编辑。

- 只有文件改了该项：使用新文件。
- 只有浏览器改了该项：保留浏览器内容，包括用户主动清空的正文。
- 双方独立修改不同字段：合并；带唯一稳定 id 的数组按记录合并，不按行号对齐。
- 双方改同一项：把两份内容记录在 cacheReview.pending；正文／说明先保留用户暂存，其他数据先使用文件，顶部明确显示核对入口。用户逐项选择后，两份及选择结果进入 resolved 归档。
- 新页面从文件加入，旧页面或业务结构已不兼容时不强行套用缓存；保留完整候选内容供核对，不能把它静默丢掉或宣称自动迁移成功。

旧缓存没有 baseModel 时无法推断编辑先后。独立的用户文字和有效视图进度保留；差异业务数据或同一段正文进入核对，不盲目覆盖。旧内容中的未知字段和原迁移归档继续保留。

冲突未处理时阻止只读／PRD 交付导出；可编辑副本始终可保存，包含冲突候选与归档，以便继续处理。只读文件启动以文件模型为准，不能由查看者旧缓存修改已交付正文和说明。

## 适用边界

本地保存不读取其他浏览器中尚未写入文件的缓存，也不自动升级其他工作 HTML。旧文件在用户要求时才接入；先在副本复现并检查业务模型、缓存校验和导出入口。旧结构无法自动恢复时，保留候选文字、草稿及数据，按原页面结构迁移后再验证。

正文迁移仍按 [PRD 约定](prd-template.md)；不得将旧章节再次自动塞进全局描述。升级旧文件时不删除用户已写文字、原始模型或附件。

## 验证

`node scripts/verify_revision.cjs` 覆盖同身份文件更新、独立用户正文、同字段冲突与处理、用户清空、稳定记录合并、新页面、无基线旧缓存和只读边界。`node scripts/verify_file_save.cjs` 通过真实本机 HTTP 服务和临时 HTML，检验正文／草稿／说明自动落盘、独立浏览器存储重开续写、源代码与身份保留、过期窗口拦截、断开失败、关闭提醒及多窗口正文保护。临时 localStorage 只在隔离运行环境中使用。

真实浏览器再用隔离文件核对：先输入正文，修改该文件的另一字段后重开，确认两份修改都在；同一字段修改时能对照、选择并重开。不要用用户正在编辑的页面做破坏性验证。

`python3 scripts/verify_local_save.py` 检查真实临时文件及 HTTP 保存、版本冲突、拒绝其他站点、原子写入失败、绑定启动器、重复打开及闲置退出。`node scripts/verify_local_bridge.cjs` 检查免选择文件自动保存、保存中继续输入、导出移除连接及离线／快捷键不触发选文件。真实浏览器还须填写、读回磁盘、重开并验证说明和草稿。
