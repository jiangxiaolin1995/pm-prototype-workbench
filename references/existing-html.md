# 已有 HTML 转为三栏工作台

用户只需提供已有 HTML 或其路径。先读取文件，用可观察到的页面与流程判断结构；已有信息足够时直接转换。此模式是保留业务的适配工作，不是把文件内容填进模板 JSON，也不能把截图放在中间冒充原交互。

## 小屏幕中的设计画布

先从源 HTML 或设计稿确定实际画布宽高，并写入页面的 `canvas` 配置。长网页可保留自然高度；固定 H5 设备保留原宽高。100% 时工作台窗口变小只缩小外层可见区域，提供横向和纵向滚动；用户可选择 75%、50% 或适应窗口等比缩放整个原型，不单独压缩设备宽高、文字或按钮；已有列表、弹窗和内部滚动继续运行。原业务的媒体查询必须针对自身画布（容器查询或完整接入的内联 iframe），不能因宿主变窄而再次改排版。业务内容与标注在同一坐标系，窗口矩形除以当前比例后再绘制覆盖层，外层滚动和缩放后重绘标号，按页面恢复比例及滚动位置。原 HTML 已有 zoom/transform 时先确认设计尺寸与坐标链，避免套用第二层比例；改变工作台比例不能重建业务 DOM 或丢失输入、弹窗及说明草稿。转换完成后在窄窗口与矮窗口实际操作，并检查导出仍保留这些能力。

## 确定保留内容

读取 HTML、已有 README 及它实际引用的本地 CSS／JS／图片。先记录页面入口、业务表单、弹窗、筛选、分页、校验、数据联动、保存／取消、原有导出、键盘操作及相关数据。保留字段、记录 ID、数据快照来源和业务术语；不从示例模板引入新的分类、限制或演示需求。

运行原型，选主要流程建立转换前基线。必要时写一组能同时跑在原文件与转换文件上的业务回归，重点覆盖会受布局或状态适配影响的规则。不能只比较按钮数量或截图。

默认另存 `MMDD-项目名-三栏工作台.html`，保留源文件并记录摘要；用户要求原地修改或本身已是工作台时先备份再迭代。创建新工作台要隔离它的缓存；迭代已有工作台要保留 `artifactId`、快照键和说明编号，不能让已有标注失踪。

## 接入外壳，尽量保留原代码

优先保留源 HTML 的业务 DOM 和事件实现，通过少量适配把它们放进中间区域。左侧以产品为一级分组，将产品全局说明和真实业务页面放到二级菜单。选择合适方式隔离样式、全局变量和事件，避免模板的通用类名、表单样式及监听器覆盖原业务。

先为源页面建立「需求、产品、端、页面」映射，按 [模板地图](template-map.md#产品端与页面归属) 接入产品分组，二级页面标明需求与端。多个文件里的同名页面不能合并；工作台页面 ID 必须唯一，并映射回各源文件自己的页面 ID。原业务 DOM ID 可保留在各自作用域内。已有工作台迭代只补归属元数据，不重建页面 ID 或说明编号。端名未知时明确标为未标明，不猜测“首页”一定是移动端。

每个产品的左侧二级菜单首先是「本产品全局说明」，后续为其真实页面，中间不增加菜单或页面 Tab。产品正文独占中间大正文区，直接填写、自动暂存，以稳定产品 ID 独立保存并适用于该产品所有端与页面，默认留空。业务页面保留原 ID、模型与交互；弹窗、空结果等仍属于页面状态。右侧保留原研发说明区，进入业务页显示对应的编号说明。

在业务需求目录之前固定添加「全局内容」首项，中间提供单一正文区，默认空白，工作文件直接显示正文输入框，填写自动暂存；只读导出显示纯文本。用独立 `model.globalContent` 与工具视图状态承载，不把全局菜单加入源业务路由或重新编号。切换全局菜单也要先保存业务 UI，返回恢复未完成输入、弹窗和说明草稿。移除目录标题下的全局说明框，保留首项菜单。保留源文件已有全局内容及全局文字数据，不自动汇总、合并或代写。

- 全局 CSS 需要限制作用域；旧版基于整个屏幕的断点，要按中间实际可用宽度重新验证，必要时改为容器查询。
- 模拟弹窗与遮罩限制在中间，原型内部滚动仍能使用；不能覆盖需求目录或右侧说明。原有 `body` 滚动锁、`inert` 和焦点约束也要限制到业务区域。
- 中间顶部用紧凑左右布局：左侧当前产品、端和标题，右侧需求路径，页面导航只在左侧；各页状态和定位、拾取工具并排。全局正文不再放在中间顶部或右侧常驻框；保留归属固定可见，窄屏正常换行，不再叠加重复标题或常驻提示。
- 工作文件只保留查看原型，提供小型「选位置写说明」按钮，取消独立写说明模式；每次点按钮只拦截一次目标选择，选中后立刻恢复业务，下次需要再点按钮。仅在选中位置后显示新增文本框，保存不重建原业务 DOM；已有说明可直接点击原条目编辑。始终保留业务的点击、输入和键盘事件。同步检查原代码的全局键盘监听，避免 Esc 取消选位置时顺便关闭弹窗。
- 已有说明使用原位编辑：在原编号旁把正文替换成输入框，保存/取消仍留在该条；不弹窗、不跳到顶部另开编辑区，不重建中间业务 DOM。编辑表单与编号定位区分开，沿用原说明 ID 和草稿缓存。新建/编辑输入框默认加高，内容超出时自动增高至完整显示；检查输入、粘贴、草稿恢复和宽度变化，不能只去掉 CSS 上限却不计算实际高度。
- 按 [元素选择约定](element-targeting.md) 接入所有可见业务元素：直接选择事件实际命中的元素，不用 `closest('[data-anchor]')` 把文字、图片、单元格一律提升成预置大区域。动态列表补稳定业务键，保证重绘后定位；指针按下与随后点击均要隔离，禁用控件也能选中。保留原有焦点、`tabindex`、ARIA 属性和正常业务事件。
- 原来的分页、菜单等可能使用 `data-page`。保留业务行为并给内部属性加命名空间，避免与工作台目录的 `[data-page]` 冲突。
- 对业务重绘后的行、标签和控件重新挂稳定锚点；彩色边框和浮动标号跟随滚动、缩放及滚动容器裁切。区域框只覆盖当前场景实际可见的目标，不拦截业务点击；同编号的边框和两侧数字使用同一颜色。若用观察器更新锚点，排除自身覆盖层重绘，避免循环。
- iframe 只在确实需要样式／脚本隔离时使用；必须同时解决锚点、跨场景定位、当前数据序列化及单文件离线导出。不能只引用原文件路径，也不能以 iframe 装载成功作为转换完成。

不要为了适配而删掉字段、重写成缩水演示、把可操作页面换成静态图，或全局禁用事件。原版业务 CSV 导出等功能与工作台的 HTML 导出分开保留。

## 状态适配

按源文件实际模型实现少量适配入口。名称可变，职责要清楚，例如：

```js
snapshot()          // 返回可序列化的 { data, ui }，不返回 DOM、函数或循环引用
restoreUI(ui)       // 恢复筛选、当前页、弹窗、表单值与必要滚动，不改已保存业务数据
showPage(pageId)    // 切换已有页面，保留它的未完成输入
reveal(note)        // 仅在目标未显示时恢复定位所需的场景
```

`data` 保存已提交的数据；`ui` 单独保存表单、配置草稿、当前分类、筛选、分页、选项展开及必要的滚动。Set／Map 在序列化边界转换，再在恢复时重建。特别检查「已保存配置」与「未提交配置」的隔离，不能因切页、定位或导出自动提交。

多产品来源的业务状态分别保存，页面 UI、说明和草稿以唯一 page ID 区分；没有原始联动关系时不能共享数据或缓存键。仅增加 `navigation` 不能替代业务状态隔离。补归属时保留已有文件的缓存身份；目录切换后中间固定归属和右侧说明归属必须一致，导出完整携带产品、端和页面映射。

不得假装已经读入用户在另一浏览器／原文件缓存里的修改。无法取得时明确转换基于文件内数据。密码等原文件本就不持久化的临时输入仍不写进缓存或导出。

说明默认只迁移原文件已有说明，或整理用户明确提供的说明文字；不得根据控件、代码或常见做法主动生成业务规则、注意点和验收标准。原文件没有说明且用户未要求代写时，右侧留空，保留手动标注入口，不预置编号。用户明确要求撰写时才在指定范围内补充。

已有或用户添加的说明绑定真实页面、场景、稳定锚点。动态记录使用业务 ID；说明目标实际可见时只更新高亮，不重新构建业务界面。目标存在于 DOM 但被隐藏、inert 或 CSS 隐藏时仍需恢复；同一表单中仅展开对应选择器，不用旧场景快照覆盖当前输入。标号和右侧说明使用统一 `data-note-locate` 入口，不借用业务 click。

原有工作台级文字继续用 `model.globalNotes.prototype` 和 `model.globalNotes.notes` 保存，非空时移入左侧「全局内容」正文下方，分开标明原归属，不能自动合并或填到各菜单；产品正文独立用 `model.productGlobalContent[productId]` 保存；原 `menuGlobalContent` 非空正文按原需求与端分别保留在所属产品全局页下方，不合并、不删除。旧 `directory` 字段继续保存在模型中，不再渲染、不自动合并，旧模型缺失时补空值；不重置其他状态或缓存身份。实现 `noteEntryAnchor(note)` 或等价入口映射：按已有说明的场景、记录 ID 和嵌套区域，找到能打开下一层的可见业务按钮。将内部说明聚合成该按钮旁的一个空心数量标识，与本按钮的实心编号并列；点击复用定位函数打开下一层。没有实际入口关系的隐藏状态只保留右侧说明和定位菜单，不伪造父子关系，也不额外列出一排说明。

## 导出与验收

沿用 SKILL.md 的完整模型、只读、草稿阻断与文本转义约定。多段内联脚本的源页面，应在所有脚本节点已进入文档后捕获完整外壳，或在构建时保留静态源；不要在第一段脚本执行时克隆尚未解析完成的文档，导致导出缺少后续业务代码。运行后的临时 DOM 不充当状态来源。

按 SKILL.md 的默认交付规则，导出检查在隔离环境拦截下载；默认只在内存中验证。确需浏览器验收时，将捕获的结果写到临时验证目录再检查，不主动触发用户浏览器下载只读预览。复验：

- 说明来源符合用户提供的内容或明确代写要求；没有说明时空状态可用。编号与高亮测试需要的临时说明只写在验证副本中，不进入交付文件。
- 转换前后的关键业务结果一致，数据与字段保留；正常、空结果和校验失败等已有状态仍可操作。
- 同一需求涉及多产品多端时，左侧按产品分组，页面注明端及需求；同名页面分别输入、写说明、切换再返回，状态不串页。中间和右侧始终显示同一归属，导出重开一致。
- 目录标题下、原型标题和右侧没有重复的全局框。每个产品的第一个二级菜单为本产品全局说明，后续页面也放左侧；产品正文独立自动保存、完整增高，跨产品不串内容。旧工作台级文字在首项全局内容页仍可读写，导出全部纯文本只读。
- 首个「全局内容」菜单可填写整份工作台共用的正文，切回业务保留进度；实际导出后仍可从首项阅读完整内容，无正文编辑入口。旧缓存缺少该字段不影响原数据和说明。
- 查看模式可直接选择位置填写说明，选中后业务控件照常可用；每次显式选位置只消耗一次点击，下一次需再点按钮；Esc 取消选位置不关闭弹窗。切换需求保留业务输入。
- 点选没有预设标记的文字、图片、按钮、禁用控件、表格单元格与弹窗子元素，保存后高亮必须精确对应；父层可选。列表插入或排序后仍定位同一记录，删除目标后提示失效，不指向邻项；工作缓存和只读导出都能恢复位置。
- 弹窗关闭或嵌套区域收起后，父级按钮旁有内部数量标识，逐层点击能到达真正的目标；同一表单的当前输入不被旧说明快照覆盖。
- 点击中间标号或右侧正文，都高亮同一位置和同编号说明；不会误触原来的新增／保存按钮。键盘也可定位。
- 点击显示中的框线或框内区域也能联动到右侧说明；框线不误触底下业务，内部输入框继续获得焦点，按钮和选择器继续原行为。点击内部控件不得整页重绘、清空输入或强制滚动中间区域；嵌套锚点匹配最近的已标注区域。
- 工作页及只读文件默认显示不同颜色的区域框，右上角开关可隐藏；关闭时先隐藏全部框，点击编号或说明后只显示对应框，换编号替换该框，开关仍关闭。验证点击与键盘定位、两侧颜色一致、右侧同步高亮；切页不重置开关、不清空业务输入。再次打开文件默认显示边框。
- 新增记录后为它标注，导出再定位，仍指向该记录；现有和新增记录都随模型导出。
- 只读文件的业务交互可用，文字可读、可复制、可定位；没有写说明或修改说明的入口。工作文件仍可继续标注。
- 所有必要资源内联，离开原目录仍能使用；若源文件缺少资源或依赖无法离线保留，先说明具体缺项，不能默默交付失效按钮。

默认只交付工作 HTML；用户明确要求时才另行导出、下载或提供只读成品。回报实际保留并验证的交互，指出任何未能验证的依赖，不把“外壳显示正常”说成“原交互全部保留”。
