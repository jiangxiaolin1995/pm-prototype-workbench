# 把截图还原到三栏工作台

收到一张截图就可以做。交付一份真实可编辑的工作台和逐图对比结果。截图为中间业务页提供外观依据，左侧目录、右侧说明、自动保存与手动只读导出沿用工作台。下面的分区校正只改有画面依据的外观，不扩大业务交互或研发说明的写入范围。

## 读取原图

1. 打开附件原文件，读取显示方向和实际像素宽高。以原文件为准，聊天缩略图可能经过缩放。保留原图，辨认页面边界、可见文案、图标、栅格、留白、字体、图片裁切和控件当前状态。
2. 记录图像尺寸和设计视口。比如一张 780 × 1688 px 的图在已知 DPR 为 2 时对应 390 × 844 CSS px。未知倍率时，优先沿用同一页面已确认的设计尺寸；仍未知就以原图尺寸按 1× 建立可复核基准，在交付中注明。局部图只还原可见部分。长截图按连续内容还原，已知设备视口用于滚动预览，全长用于对比。
3. 多图逐张对应页面或状态。只从可见标题、用户标注和已有文件确定归属。新工作台用干净骨架；追加到已有工作台时保留页面身份、用户说明和草稿。同时有原 HTML 时，按[已有 HTML 转换](existing-html.md)保留原流程，截图指导本次外观修改。

## 还原可选的页面元素

- 把业务页接入[业务适配器](template-map.md)，按设计视口配置 `pages[id].canvas`。用 HTML/CSS 还原布局、文字、按钮、输入框、标签、图片和图标。工作台外壳适应窗口，内部画布等比缩放。取景时计入原图可见的安全区和业务导航，工作台工具栏留在画布外。
- 每个可见的独立元素都要能拾取。按钮内图标和文字分别有节点，列表项与重复控件有稳定键，弹窗内可见元素落在当前业务根内。用元素承载需单独标注的装饰内容。照片、封面等原始素材可作为单个图片元素，缺素材时可从原图裁出对应图片区域，保证 HTML 离线可用。禁止把整张截图铺作页面再覆盖透明热区，也不要把一组可拆分的控件烘成一张图。
- 按截图呈现当时的选中、禁用、展开或弹窗状态。只有用户明确说明、明确标注的转场或已提供的原 HTML 能确定业务动作。按钮去向、滑动结果、提交反馈、权限与扣费等无法由静态外观确定时，控件保留可标注的外观，业务动作留空。多张状态图可分别从工作台预览，提供顺序本身不构成跳转规则。缺失的 PRD 正文保持空白；画面文字、已确认转场和对比结论不自动转成右侧研发说明，写入条件见 [内容来源](../SKILL.md#内容来源)。

## 同尺寸验收

1. 在真实浏览器打开**实际生成的工作 HTML**并进入对应页面或状态。设定参照视口、DPR 和 100% 画布比例，对齐截图的滚动位置、字体与素材加载状态。在验证副本中清除拾取、高亮、编号与标注框，只截业务根。画布大于中栏时，在验证窗口给画布足够的可见空间再截取。长图按实际滚动内容捕获，核对固定头尾出现的位置。不要用独立手写预览代替工作台产物截图。
2. 核对取景边界和输出像素宽高。遇到裁切或尺寸不符，修正取景、设计视口或 DPR 再截。同尺寸后制作并排对照图，左边原图、右边还原图，两边各保留原始像素。可用随附工具（Python 3 与 Pillow）：

   ```sh
   python3 <skill-dir>/scripts/compare_screenshots.py "/项目/原图.png" "/项目/工作台实截.png" --output "/项目/同尺寸对照.png"
   ```

   工具按图像方向读取，透明像素按白底展示，并为两张图统一色彩空间。若原稿规定了透明素材的底色，先用该底色确定参照画面。工具拒绝尺寸不同的输入和已存在的输出文件。复核下一版时另取输出名。有等效图像工具时也可按同样规格对照。
3. 按下方分区流程检查并局部修正，然后从同一业务页重新截图。记录仍可见的差异，例如缺失原字体或模糊区域。尺寸相同只证明取景规格相同。
4. 用隔离的工作副本实测[元素标注](element-targeting.md)。逐类选择文字、图标、图片、按钮内子元素、列表项、禁用控件及弹窗内元素等本页实际存在的目标。进入一次「选位置写说明」，选中目标，在右侧填写并保存，再由右侧说明回到同一元素。检查重开后定位、普通交互及已确认的跳转。抽查有遮挡、重复或嵌套的元素，修复选到外层或错行的情况。测试文字留在验证副本中。
5. **主入口直接打开真实三栏工作台**，不要让用户先进入一张图片报告再寻找 HTML。附各图的同尺寸对照、残余差异和未确定的业务动作。若另做对照页，默认并排展示参考原图与实际 HTML；可以抽取实际产物的同一份业务 DOM／样式隔离展示，不能重新写一份看起来相似的预览。固定渲染截图只用于明确标示的叠加、差异图和验收证据。图片素材可保留 img，文字、控件和布局必须仍是独立可选元素。没有原图、没有实截或未做视觉对比时标为待验；不等待用户补齐未知交互才交付还原稿。

## 分区对比与局部修正

1. **先保存整页基线。** 初稿按现有流程完成正常目视校正，再保留 HTML 和实截。比较方法或版本时，两版沿用相同原图、视口、DPR、字体与素材加载条件；说明各自校正轮次，不刻意降低基线质量。
2. **按画面含义划分区域。** 例如页头、主要卡片、列表、底部导航或弹窗。记录各区域名称及原图像素坐标 `[x, y, width, height]`，只为本次实际区域建表，不固定套用某个示例的分区。原图与实截在相同坐标裁切，不能各自裁到“看起来最像”的位置。
3. **先定位误差来源，再改对应区域。** 先检查取景和整体几何，再看区域位置、尺寸、间距、文字换行与字重，最后检查颜色、圆角、图标及装饰。背景取色避开文字、边缘和阴影；复用原图中的独立图片素材，不能以整张图或整组控件替代 DOM。若问题来自共用字号或间距，修改共用样式并复查所有受影响区域；保留原节点、稳定 ID、已有交互、说明及草稿。
4. **用差异图辅助，不把指标当验收结论。** 可在上面的同尺寸工具中追加 `--regions` 和 `--details`：

   ```sh
   python3 <skill-dir>/scripts/compare_screenshots.py "/项目/原图.png" "/项目/工作台实截.png" --output "/项目/第2轮对照.png" --regions "/项目/分区.json" --details "/项目/第2轮分区"
   ```

   `分区.json` 为数组，例如 `[{"name":"页头","box":[0,0,390,120]}]`，坐标须按实际原图调整。工具输出整页及各区域的对照图、差异图、`metrics.json`；分区目录必须尚不存在。对照图保留原始像素，差异图把差异增强为深红色，RGB 平均绝对误差范围为 0–255，越低越接近。它不是“还原率”；大面积背景、压缩和字体抗锯齿会影响指标。区域可以重叠，不能把其误差简单平均成整页结果。
5. **修完一处，回查整页。** 从实际工作台再截同一状态，查看修改区、相邻区和整页差异；发现其他区域退步时修正或撤回对应改动。保留每轮结果，不覆盖前一轮证据。完成后实际检查文字选择、控件和标注定位，确认没有用截图蒙层取代还原，也没有补出未知业务动作。
6. **如实报告完成程度。** 明显偏差已修复且进一步改进受原字体、素材或截图清晰度限制时，列出剩余差异；不为追逐低误差反复扭曲结构。多一轮人工校正的改善不能宣称为某个模型或开源引擎的优势，未实际调用的项目不能写成已接入。
