# PRD 纯文字需求说明

新建、升级或转换工作台时阅读。本约定只定义文档工具，不授权补写业务规则。

## 左侧结构

```text
需求说明
  全局描述
  上线后数据需求
  埋点说明
产品名称
  本产品全局说明
  业务页面…
```

三个需求入口属于整个工作台，不按产品或需求复制。正文中由用户自行注明适用的产品、端与页面。产品目录及原型页面继续保留，右侧仍是研发说明；文档页只提示适用范围，业务页显示原编号说明。文档不占业务页数和说明编号，不修改业务路由或页面 ID。

## 只填文字

- **全局描述**：填写需求背景、目标、范围及共用描述，具体内容由用户决定。
- **上线后数据需求**：填写上线后希望观察的数据、统计范围和观察时间。不是上线排期，不代写指标口径、目标值或发布计划。
- **埋点说明**：有埋点时填写事件、触发时机等已确认文字；没有可以留空。入口默认存在，不增加开关或必填校验。

每页默认直接显示一个大文本框，至少 420px。从「打开工作台」入口进入后，输入自动写回工作 HTML，浏览器暂存只作备份；粘贴长文、重开、改变宽度后完整增高。只显示纯文本并保留换行；格式符号和 HTML 标签按原文显示，不渲染 Markdown、表格或图片。没有标题/列表/表格工具，没有附件上传、章节增删、预览确认、版本或负责人表单。

## PRD 的组织与检查

保留现有三个文字入口、产品目录和右侧说明。以下供用户填写，以及明确要求 Codex 整理文字时参考；不是自动生成正文的清单，右侧写入条件见 [内容来源](../SKILL.md#内容来源)。不创建额外必填字段，不把章节、示例或默认规则预填到正文。全局、产品、数据与埋点正文页的「填写参考」默认展开；只有右侧研发说明的「填写参考」默认折叠，用户可手动开合。开合只影响提示显示，不能改变正文、业务数据或草稿。只读页面、打印与导出 PRD 正文不展示这些填写提示。

| 位置 | 建议组织的内容 |
| --- | --- |
| 全局描述 | 背景与目标、目标用户与场景、本次范围及暂不做的内容、涉及的产品／端／页面、跨页面主流程与分支、需求共用规则、核心流程验收依据 |
| 本产品全局说明 | 本产品的角色权限、数据来源与更新方式、跨页面状态、共用异常与验收；注明适用端与页面 |
| 页面右侧说明 | 当前元素的前置条件、操作与结果、默认值或校验、相关异常边界、可检查的预期结果 |
| 上线后数据需求 | 要观察的结果、指标口径与统计对象、时间范围、已确认的基线／目标或判断标准、数据来源 |
| 埋点说明 | 对应的数据观察目标、适用产品／端／页面、触发与不触发条件、事件及参数含义、重复／失败区分、核验方式 |

全局描述按需补充上线依赖与先后安排、待确认问题、重要变更；兼容性、性能、隐私等有具体要求时再写。上线安排与上线后数据观察分别描述，不把发布计划迁入数据需求。验收标准说明功能是否按要求完成，数据观察说明上线后的效果。接口和数据库的实现方案可链接研发文档，不作为每份 PRD 的必填正文。

同一文件有多个需求时，在全局描述按需求名称分段，标明各自范围与关联页面；同一需求跨多个产品或端时，说明各处的职责与配合关系。沿用「产品 → 端 → 页面」目录及产品级全局说明，不拆分同一产品、不新增端级正文，也不重复同一条规则。

用户提供内容或要求查漏时，检查需求是否交代了背景与目标、范围、完整流程、规则与相关异常、验收依据。发现缺项在交付说明中列明缺什么、影响哪里；用户未授权设计时不提供未经确认的默认值，不把原型行为反推成最终规则。普通局部改动只检查受影响内容，不强制补完所有章节或阻塞其余已授权工作。原型实现与说明有差异时提出核对，不擅自覆盖任何一方。

缺失内容默认留空，全局描述不设置 placeholder 或示例正文。用户指定写入的文字按原意放到指定位置，不要求用户再抄一遍；已有正文、说明和草稿保留。用于实现交互的需求描述，不自动转为页面研发说明，也不据此补充前置条件、校验、异常或验收文字。用户明确要求起草研发说明时才在指定范围起草，未确认的规则不写成既定事实。填写参考与 placeholder 不能存成正文或说明。页面右侧依旧一个正文框，通过「选位置写说明」选择可见业务 HTML 元素，见 [元素选择约定](element-targeting.md)。

## 模型与迁移

- `model.globalContent`：全局描述，沿用原字段和缓存。
- `model.dataRequirements`：上线后数据需求，默认空字符串。
- `model.trackingContent`：埋点说明，默认空字符串。
- `model.workspaceView`：`global` / `data` / `tracking` / `product` / `prototype`。`activePage` 始终是原业务页，不混入文档 ID。
- `model.requirementTextScroll` 保存 data、tracking 正文滚动；全局描述沿用 globalScroll。

`normalizeRequirementTexts` 只补缺字段；全局描述只取用户原有的 `globalContent`，不能自动汇总旧 PRD 或填入示例。旧 `prdDocuments` 的正文、章节和附件保留在原模型内，不自动塞进全局描述。原 tracking 沿用一次性迁移进入埋点说明；旧上线安排不转成数据需求。

`plainDocumentsMigrated` 标记旧迁移；`globalDescriptionUserOnly` 标记全局描述已改为仅保留用户内容。升级时若已迁移正文仍与旧自动拼接片段完全一致，移出这一片段，原值存入 `globalDescriptionMigrationArchive`；前面已有的用户文字保留，片段被编辑过则不清除。只处理一次，之后新输入的文字正常保存，不能每次打开都清空。可编辑副本与只读载荷继续携带原始内容和归档数据。

旧 `workspaceView: requirement` 进入全局描述。旧产品正文、globalNotes、菜单文字、说明与草稿、业务状态和缓存身份均保留。

主要入口：`requirementTexts`、`normalizeRequirementTexts`、`renderRequirementDirectory`、`renderRequirementContent`、`switchRequirementDocument`。`#global-menu` 继续指向 `#global-content-panel`；两个新增入口用 `[data-prd-document]`，正文复用 `#requirement-panel`。切换时保留业务表单、弹窗、说明草稿和各页滚动。只读启动以文件正文为准，不能让查看缓存覆盖。

## 手动保存与导出

- **保存可编辑副本**：保存三份文字、产品正文、说明及草稿和业务状态，readOnly 为 false；新的快照键隔离副本缓存，不因未保存草稿阻止备份。
- **导出只读 HTML**：沿用说明草稿、失效位置和未处理内容冲突校验。正文仅可查看复制，不能修改；业务原型继续可交互、缩放和定位。原工作文件继续可编辑。
- **导出 PRD**：输出 Markdown 文件，包含全局描述、上线后数据需求、埋点说明、产品正文及页面编号说明；编辑界面仍只收文字。

所有下载都由用户手动触发。默认只交付可编辑工作 HTML，不主动导出、下载或附送只读成品。

## 验证

先对实际工作文件运行 [产物验证](verification.md)。模板回归运行 `node scripts/verify_prd.cjs --jsdom /已安装路径/node_modules/jsdom`，检查三个固定入口、纯文本与转义、独立保存、不自动填入旧章节、旧自动填入内容清理及用户正文保留、原上线安排不误分为数据需求、原始附件保留、表单/草稿恢复，以及实际工作副本、只读和 PRD 导出。下载在内存拦截。

再运行受影响的产品目录、元素选择、原位编辑和导出回归。真实浏览器检查仅右侧研发说明的填写参考默认折叠、其余正文页参考仍展开，开合不改正文；检查输入框默认空白、长文完整展开、窄屏、菜单切换、弹窗内元素选择与后续原交互、只读文字和业务交互。交付提供绑定实际 HTML 的编辑入口。
